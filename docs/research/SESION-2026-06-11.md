## 3. Conclusiones por Área

### 3.1. Sobre el Giro UX-Céntrico

**El cambio de paradigma es correcto y está justificado.** La observabilidad tradicional (métricas de servidor) no responde la pregunta que realmente importa: "¿qué está experimentando el usuario?". Las plataformas enterprise (Datadog, Dynatrace) ya integraron RUM con el resto del stack, pero a costos prohibitivos. El nicho "Bajo Recurso + Alta AI" está completamente desatendido.

**Conclusión**: IntellOps ocupa un espacio legítimo de I+D+i que ninguna plataforma existente cubre.

### 3.2. Sobre las Herramientas de la Industria

| Conclusión | Evidencia |
|-----------|-----------|
| **Grafana LGTM** es la base correcta para IntellOps | Único stack OSS completo con self-hosted y footprint manejable (~2GB) |
| **Ninguna herramienta** cubre nuestro nicho | Todas asumen cloud o recursos abundantes |
| **Netdata** es el complemento ideal para self-monitoring | 150MB RAM, ML en edge, eBPF nativo |
| **Datadog/Dynatrace** son referencias de features pero inalcanzables en costo | $500K+/año vs nuestro target $0/mes |
| **OpenTelemetry Browser** es el talón de Aquiles de la industria | Es experimental, unspecified, y es donde podemos investigar |

### 3.3. Sobre Frontend Observability

**El campo está inmaduro académicamente.** Hay mucha documentación de vendor (Google, Datadog) pero pocos papers revisados por pares sobre:
- Correlación de métricas UX con reclamos de usuarios
- Bundle óptimo para agentes RUM con feature-set completo
- Privacidad por diseño en recolección de datos de frontend
- Uso de señales de frontend como quality gates en CI/CD

Los Core Web Vitals (LCP, INP, CLS) son el estándar de facto pero tienen limitaciones serias: solo Chrome, datos agregados, sin trazabilidad, ventana de 28 días.

### 3.4. Sobre el Agente RUM

**Es el componente más crítico y donde más I+D+i podemos hacer.** No existe un agente RUM open-source que combine:
- Core Web Vitals out-of-the-box
- Trazas OpenTelemetry desde el navegador
- Error tracking con stack trace
- Contexto de sesión + geolocalización
- Bundle < 20KB

**Target alcanzable**: 19.5KB estimado con tree-shaking + custom exporter. Datadog RUM pesa 50KB.

### 3.5. Sobre los Research Gaps

Identificamos **5 campos abiertos de investigación** donde IntellOps puede hacer contribuciones originales:

| Gap | ¿Por qué es investigable? | ¿Quién lo aborda? |
|-----|--------------------------|-------------------|
| **Agente RUM < 20KB OSS** | No existe en el mercado. Los más cercanos (Grafana Faro 10KB, sin OTel completo) o son cloud o incompletos | Federico (Fase 2) |
| **LLM local para RCA** | Todos los asistentes AI (Bits AI, Davis AI) son cloud. Nadie demostró RCA con LLM 1B en CPU local | Romeo (Fase 2) |
| **User Health Score predictivo** | No existe estándar abierto. Las implementaciones existentes son propietarias (Datadog, Dynatrace) | Romeo (Fase 2) |
| **Quality gates OTel en CI/CD** | Ninguna herramienta actual ofrece señales OTel como gates. Lighthouse CI es solo lab | Santiago (Fase 2) |
| **Stack completo < 2GB RAM** | No hay stack que ofrezca RUM + logs + trazas + métricas + AI en < 2GB. Datadog requiere cloud, Grafana LGTM requiere ~2.5GB | Todo el equipo |
